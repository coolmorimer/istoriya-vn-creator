Дальше: циклические/временные зависимости, полная приёмка сложных карт, предметная анимация, завершение визуального редактора меню и общей матрицы ТЗ. Базовая диагностика не доказывает проходимость всей истории; ядро взаимодействий не означает завершённый универсальный движок.

Базовая архитектура подходит: React отвечает за редактирование, собственный формат — за данные, компилятор — за Ren'Py. Главный продуктовый разрыв — секундная шкала и редактирование отдельных действий без отображения накопленного состояния сцены. Автор вынужден мысленно восстанавливать, какой фон и персонажи должны быть видны. Главная перегружена обучением и каталогом настроечных шаблонов. Многие контролы доступны одновременно, независимо от задачи.

На исходном состоянии этой итерации проходят 52 теста. Они проверяют отдельные операции и генератор, но не доказывают исправность всех пользовательских сценариев. Остались незакоммиченные изменения предыдущей итерации; они сохранены. Результаты сентябрьского аудита находятся в PROJECT_AUDIT_0.1.2.md и PRODUCT_AUDIT.md; текущие требования к редактору кадров заменяют прежний приоритет видеомонтажа.

Найденные конкретные проблемы:

- В обычном сценарии холст использует начальный фон и постоянные слои, не учитывая предыдущие действия. Выбранный фон/спрайт может не отображаться.
- Добавление действия и вставка копии переключают нижнюю вкладку, что теряет контекст работы.
- Перестановка массива в timed-сцене не меняет исполнение, которое определяется временем. Нельзя выдавать это за изменение порядка кадров.
- Главная смешивает проекты, обучение и шаблоны без контента; настройки относятся к скрытому текущему проекту.
- Store клонирует весь проект и сохраняет его историю на каждое изменение поля. При больших проектах это вероятный источник задержек; нужен замер и затем история команд/патчей.
- Подписка компонентов на весь store вызывает лишние перерисовки. Синхронные файловые операции в Electron могут блокировать приложение.
- Сохранение активного проекта, библиотеки и отдельной папки не образует одну транзакцию. Предыдущая .bak не заменяет историю ревизий.

## Решение по Rust

Рекомендуемый кандидат: **React + Tauri 2/Rust для оболочки + Ren'Py для игры**. Tauri использует системный WebView и позволяет сохранить существующий веб-интерфейс ([архитектура](https://v2.tauri.app/concept/architecture/), [введение](https://v2.tauri.app/start/)). Это может уменьшить размер оболочки; это не измеренное ускорение нашего редактора. В установщике также находится большой SDK Ren'Py, который переход на Rust сам по себе не уменьшит.

По уточнению владельца перенос начат сразу: Tauri/Rust становится основной нативной реализацией; React остаётся интерфейсом. Rust toolchain установлен для проверки. Старый JS-компилятор временно выполняется отдельным Node-процессом, запускаемым Rust; пользовательская машина не требует отдельной установки Node. Это переходный компонент, а не заявление о переписанном на Rust генераторе. Файловое хранилище, диалоги, окно и управление процессом переносятся сейчас; Electron остаётся резервной сборкой на время проверки.

## Совместимость

Старые timed-сцены продолжают работать. Их секундная шкала доступна отдельно. Переход в последовательность шагов выполняется явно, с сохранением исходного монтажа внутри сцены и возможностью Undo. Отключённые клипы не должны внезапно начать исполняться. Одновременные клипы при конвертации становятся последовательными действиями — это изменение семантики должно быть объяснено до подтверждения.
