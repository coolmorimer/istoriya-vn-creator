# Проверка Истории 0.2.38

Бета Rust-ядра после 0.2.37. По отдельному запросу владельца подготовлена публикация установщика и исходников; [описание и инструкция поставки](releases/0.2.38.md). Полная цель конструктора и собственного Rust-проигрывателя сохраняется в [плане R1–R8](RUST_ENGINE_PLAN.md).

Проверенный EXE: SHA-256 `077eff9d919c84a1306cec9272cb36bb9ea3a270bc3fc67be50a03164a633a29`. Локальный сводный манифест — `D:/IstoriyaQA/document-038/engine-verification-manifest.json`; raw QA-профили в Git не включаются.

## Реализовано

- Rust `StoryPlan`: подтверждённый старт, порядок/продолжение сцен и типизированные назначения глав/сцен. Включены jump, choice, оба плеча condition, реакции предметов и назначения включённого RPG-мира.
- Ссылочная проверка до подготовки SDK: удалённые назначения, пустые обязательные переходы, входы и списки глав, повторные ID глав, устаревшие сцена/шаг запуска. Незавершённый проект по-прежнему можно сохранить.
- Передача отдельного `story-plan.json` с длиной/SHA-256; JS-генератор применяет готовый план без повторного `resolveStoryProject`. Изменённые представления копируют только родителей ссылок, не всю библиотеку медиа.
- Начало игры учитывает вход первой непустой главы, а карта и проверка достижимости показывают этот же старт. Порядок сцен включает свободные сцены после глав в стабильном UTF-16 порядке.
- Импорт перестал автоматически присоединять свободные сцены к первой главе. Дерево показывает их в служебной группе «Вне глав» без новой главы в документе. Сохраняются поиск, сворачивание и клавиатурная навигация.
- На карте принадлежность сцены можно явно назначить или снять через «Глава → Вне глав», с Undo/Redo. При переносе входа прежняя глава получает действующий вход по умолчанию, а не битую ссылку.
- «Упорядочить» размещает также свободные сцены, не присоединяя их к главе. Undo возвращает все исходные позиции; это проверено отдельно в нативном интерфейсе.

## Фактический EXE и игра

На собственной копии EXE отключены JS-builder, GUI-launcher, структурный валидатор и `resolveStoryProject`. Нативные сборки проходят через Rust. Повторный пакет не перезаписывает предыдущий; неверная ссылка отвергается до генератора. Повреждение документа той же длины обнаруживается по хешу.

Импортируемый QA-проект содержит 11 сцен и 5 глав, непервые входы, интерактивную дверь, варианты выбора, условие и сцену вне глав. Настоящая кнопка Windows-сборки выпустила ZIP с `storyPlanner: rust` и `storyStart: entry`, независимо от выбранной в редакторе сцены.

В этом ZIP выполнены два сценария и 11 утверждений: непервые входы, настоящий pointer-клик по предмету, его ответ перед переходом в главу, оба условия, сцена с буквальным ID `chapter:third`, продолжение в свободную сцену, Save/Load и восстановление флага. Отдельный обычный запуск достиг главного меню без тестовых аргументов.

С учётом регрессий конвейера, RPG и камеры/ключевых кадров в готовых играх проверены 7 сценариев, 48 утверждений и 2 обычных запуска без runtime-исключений.

## Интерфейс и авторские данные

Проверка карты выявила старое автоматическое изменение принадлежности при импорте; после исправления использован новый QA-профиль и пересобран EXE. Подтверждены отсутствие демо в новом проекте, 11 сцен после импорта, сохранение свободной сцены без изменения глав, поиск/показ группы «Вне глав», явное назначение в главу и Undo/Redo. Сохранённые данные повторно прочитаны через нативное хранилище. Метка «Начало игры» показана у фактического входа, а не первой карточки. Механический UI-detector не нашёл замечаний в изменённых компонентах; внешний вид редактора сохранён.

В настоящем WebView проверены End → последняя свободная сцена, ArrowLeft → служебная группа, её сворачивание/раскрытие и Enter → открытие сцены. После сборки создан ещё один пустой проект. Новый процесс приложения повторно открыл библиотеку из трёх проектов: оба пустых остались без ресурсов/действий, импортированный сохранил 5 глав, свободную сцену, вход и исходные ссылки. Соседние устаревшие кэшированные SceneId не переписаны: Rust-план использует приоритетный ChapterId только в представлении генератора.

Два native-preview достигли главного меню и вышли с кодом 0; после каждого staging удалён, основное persistent и локальное зеркало вне кэша сохранены. Второй запуск прочитал данные первого. Оба процесса редактора завершились штатно; профиль владельца не открывался.

Проверки используют собственные профили и изолированный Windows desktop, не профиль владельца и не OS mouse automation. Ограниченный QA-выход сборки не доказывает работу обычного системного диалога выбора папки. Dummy-аудио не подтверждает слышимое качество записи.

## Что остаётся

R2 ещё не завершён: миграции, остальные семантические ссылки и полнота диагностики требуют переноса. R3 пока содержит навигационный план, не полное типизированное исполнение шагов, времени, камеры и трансформаций. Условия и игровые правила, генераторы и собственный Rust-проигрыватель остаются открытыми. Установка/обновление на чистой Windows, другие платформы и полная production-приёмка этой итерацией не подтверждены. Файлы старого релиза 0.2.37 не меняются.

## Состав публикации

Установщик собирается из принятого EXE коммита `9193b3e8deb4f43a35dd9d5299983c4bf15cfed9`. Последующий релизный коммит меняет только документацию и инструменты публикации, не приложение. Перед поставкой повторно сверяются хеши всех принятых исходников, EXE и соседних runtime-модулей; разрешённые изменения инструментов фиксируются отдельно в манифесте.

Поставка содержит установщик, прежнее руководство 0.2.34 со скриншотами, четыре файла примеров, публичный манифест и контрольные суммы. Личные проекты и raw QA-профили не публикуются. Установщик не подписан; его компиляция и проверка содержимого не заменяют установку/обновление на чистой Windows.
