# Разработка и сборка Истории

Основная настольная реализация находится в `src-tauri/`. React-интерфейс использует общие с компилятором правила из `runtime/`. Ren’Py — игровой runtime, не формат исходного авторского проекта. Сохраняйте стабильные ID, совместимость старых проектов и соответствие редактора, предпросмотра и экспортированной игры.

## Окружение

- Windows x64, Node.js 22+ с npm.
- Rust stable, MSVC Build Tools и Windows SDK.
- Для установщика — Inno Setup 6.
- Официальный Ren’Py SDK 8.5.3, распакованный **рядом с репозиторием** в `../renpy-8.5.3-sdk`. Ожидаемая версия runtime — 8.5.3.26051504.

SDK не хранится в Git. Контрольная сумма официального ZIP закреплена в `.github/workflows/test.yml`. Исходники доступны для ознакомления на условиях корневого `LICENSE`; наличие публичного репозитория само по себе не даёт открытую лицензию на оригинальный код.

## Запуск разработки

Все команды выполняются из корня репозитория:

```powershell
npm ci
node scripts/collect-notices.mjs
npm test
npm run desktop:dev
```

Для web-интерфейса: `npm run dev -- --host 127.0.0.1 --port 4173`. Браузерный режим не заменяет нативную сборку игры и ограничен квотой IndexedDB. Electron — резервный путь, а не основная релизная цель.

## Проверки

```powershell
npm test
npm run lint
npm run test:sites
npm run native:test
npm run build
npm run desktop
npm run verify:release
npm run verify:keyframes
npm run verify:rpg
```

Нативные build/test и UI-сборку игр выполняйте последовательно: они используют общие runtime-ресурсы. Интеграционные проверки требуют Windows и SDK и могут занимать существенно больше времени, чем unit-тесты. QA использует отдельные копии/профили; не направляйте проверки в библиотеку автора и не устанавливайте candidate поверх рабочего приложения.

`verify:release` проверяет фактический EXE, хранилище, повторное открытие, компиляцию, экспортированную игру и обычный запуск. Это не проверка чистой Windows, всех системных диалогов или физических устройств. При исключении в журнале runtime результат считается неуспешным, даже если тестовый runner затем напечатал PASSED.

## Установщик

```powershell
npm run installer
```

Команда запускает тесты, нативную сборку, собирает уведомления о лицензиях, проверяет runtime и выпускает Inno Setup. Результат: `release-rust/setup/Istoriya-Rust-Setup-<version>-x64.exe`, `SHA256SUMS.txt` и `packaging-manifest.json`. Подпись Microsoft проверяется для bootstrapper WebView2; сам установщик Истории пока не подписан.

Для уже проверенной неизменённой нативной сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-native-installer.ps1 -SkipBuild
```

Не выдавайте старый установщик за результат новых функциональных изменений. Сопоставляйте версию, SHA EXE, runtime-модули, встроенный интерфейс и итоговый установщик. Перед выпуском сверяйте [матрицу приёмки](MVP_ACCEPTANCE.md).

## Руководство

Исходники текущей инструкции: `docs/manual034/content.json` и `docs/manual034/screens/`. Для генератора нужны Python 3, ReportLab, Pillow и pypdf:

```powershell
python -m pip install reportlab pillow pypdf
python scripts/build-user-guide.py --out output/pdf
```

Сгенерированные PDF/HTML находятся в `output/pdf/` и не коммитятся. После изменения текста проверьте ссылки, изображения, оглавление и фактически отрисованные страницы; прежнее число страниц не является приёмкой нового файла.

## Структура поставки

В Git коммитятся исходники, тесты, reusable-ресурсы, сценарии, скриншоты и документация. Установщик, игры, большие переносимые `.vnproject`, PDF/HTML и контрольные суммы публикуются в GitHub Releases. Кэши, SDK, `node_modules`, личные проекты, ключи, `.env` и raw QA-профили туда не входят.

[Карта модулей](../PROJECT_MAP.md) показывает конкретные точки входа. Исторические отчёты в `docs/RELEASE_*.md` сохраняют границы проверки соответствующей версии, а не обещания будущей функциональности.
