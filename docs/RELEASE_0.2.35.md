# Rust конвейер сборки 0.2.35

23 октября 2026. Локальная версия разработки, не новый публичный релиз и не завершение полного Rust-движка. Цель и остальные этапы сохранены в [плане Rust-ядра](RUST_ENGINE_PLAN.md) и [матрице требований](MVP_ACCEPTANCE.md).

## Реализовано

Нативные команды build/preview входят в `src-tauri/src/engine`. Rust готовит игровой GUI официальными командами Ren’Py, запускает проверку и упаковку, управляет отдельным предпросмотром и выдаёт готовый пакет. JS-компонент временно остаётся генератором исходников; запросы старого типа build/preview он отвергает, а не выполняет через старый JS-builder. Совместимый Electron/CLI-путь сохраняется отдельно.

Процессы запускаются без shell. Ожидание ограничено, вывод контролируется, traceback в любом месте сохранённого вывода отменяет успех даже при коде 0. Windows Job Object завершает оставшиеся сборочные дочерние процессы при закрытии группы; это механизм управления процессами, не security sandbox. [Семантика Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

Упаковка работает в новом каталоге текущего задания. Готовый файл сохраняется через временный файл в выбранной папке без перезаписи существующего имени; при совпадении создаётся другое имя. Используется `persist_noclobber`: он не перезаписывает цель, но это не обещание одинаковой атомарности на любой файловой системе или устойчивости к отключению питания. [Гарантии tempfile](https://docs.rs/tempfile/latest/tempfile/struct.NamedTempFile.html#method.persist_noclobber).

Генерация Android-ключа также проходит через staging, постоянный ключ не заменяется; блокировка файла освобождается ОС после завершения процесса. Повреждённый/пустой ключ не подменяется новым. Настоящая проверка JDK, APK/AAB и устройств пока не выполнена.

## Фактические проверки

Локальный манифест: `D:/IstoriyaQA/engine-035/engine-verification-manifest.json`. Он проверяет SHA EXE и 31 runtime-модуля, исходники Rust-конвейера, результаты процессов и игр. Полные собственные QA-копии остаются локально, не публикуются вместе с исходниками.

| Проверка | Результат |
| --- | --- |
| Исходники | 322 JS, 50 Rust, 4 Sites; ESLint/Vite build |
| Самостоятельная нативная сборка | EXE 0.2.35 со встроенным UI и соседним проверенным runtime |
| Отключённый прежний путь | На собственной QA-копии старый Node-builder и Node GUI-launcher заменены явными ошибками. Rust EXE всё равно создаёт настоящую игру; worker получает только compile с подготовленным GUI |
| Старые пакеты и отказ | Намеренно невалидный старый ZIP не выбран; повторная сборка оставляет SHA первого файла неизменным; повреждённый документ даёт русскую ошибку и не публикует новый пакет |
| Процессные отказы | Ненулевой код, traceback до обрезаемого хвоста при exit 0, переполнение вывода, таймаут, завершение собственного фонового потомка |

| Проекты и закрытие | Пустой проект до и после сборки; библиотека двух историй повторно прочитана в новом native-процессе, затем создан третий пустой проект; все три тестовых редактора закрыты с кодом 0 без таймаута |
| Отдельное native preview | Из реальной кнопки UI запущен Rust preview; настоящий Ren’Py достиг главного меню без runtime-исключения. Два разных временных задания используют одну ожидаемую QA-папку сохранений, второе видит постоянный маркер первого |

Суммарно в готовых ZIP: **6 сценариев / 40 утверждений**, плюс **два обычных запуска**. Отдельный preview не прибавлен к этому числу: для него пассивный QA callback добавлялся только в собственную временную папку и наблюдал главное меню/свою persistent-метку. Он не заменял экраны и не нажимал кнопки ОС. Игровые сценарии ZIP исполнялись с dummy-аудиодрайвером; отдельный UI-preview не содержал аудиоресурсов. Слышимое качество речи не принято.

Нативные UI-проверки идут через CDP собственного WebView на отдельном Windows desktop без переключения input desktop и без OS-мыши. Выбор папки сборки в QA ограничен проверенным QA-профилем; обычный системный диалог этим не проверяется. Профиль установленного редактора владельца не изменён.

Обычный отдельный preview сохраняет прежнюю семантику Ren’Py save-directory и явный родительский `RENPY_PATH_TO_SAVES`, а не переводит старые игровые сохранения в compiler staging. QA задаёт этот параметр только внутри своего процесса. В повторном preview проверены расположение и сохранение persistent-данных; это не отдельная приёмка всех старых игровых Save/Load владельца.

Финальный EXE: SHA-256 `287f4da75240053f903f37977c207ac8446be0eee1d9d17e87d1f48ef786a475`. До принятого прогона сохранена одна неуспешная попытка пересборки: rustc завершился с STATUS_ACCESS_VIOLATION. Повторная последовательная сборка и проверки финального EXE прошли; этот факт не объявляется доказательством устранения всех сбоев toolchain.

## Что остаётся

Модель документа, валидация, генерация сценария/интерфейса и игровые правила ещё должны быть перенесены на Rust с полным паритетом; собственный Rust-проигрыватель ещё не реализован. Node всё ещё включён в нативные ресурсы. Временные каталоги отдельного Ren’Py-preview пока сохраняются, как и прежде: безопасная очистка после завершения игры остаётся задачей жизненного цикла, отдельно от постоянных сохранений. Масштабные замеры производительности/памяти, Android/Linux/macOS, чистая Windows, установка/обновление, подпись и оставшиеся функции ТЗ не закрыты этим этапом. Установщик 0.2.35 и публикация на GitHub здесь не выполнялись; релиз 0.2.34 сохранён.
