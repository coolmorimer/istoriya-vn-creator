# 0.2.23 — восстановление, которое не теряется на главной

16 октября 2026. Локальная проверяемая бета. Полная production-приёмка не объявляется завершённой.

## Исправленные продуктовые дефекты

1. В0.2.22 `loadProject` принимал черновик через блокирующий `window.confirm` и возвращал его как уже сохранённый. Библиотека оставалась старой; открытие карточки заменяло восстановленный текст. Прямой repro настоящего store с in-memory persistence подтвердил потерю принятой версии и0 durable writes (`recovery-0222-baseline-receipt.json`). Это source/store repro, не ретроспективный native-тест старого установщика.
2. HTML Blob-download в собственном native WebView не создал файл в заданной QA-папке и не завершил download-event, хотя UI сообщал о подготовленной копии. Rust-копии теперь используют настоящий атомарный file write и save-dialog; успех только после результата, отмена и ошибка не считаются сохранением. Browser Blob остаётся браузерным fallback. Ссылочная копия — отдельный явный выбор, raw JSON повреждённого draft — отдельный файл.
3. Реальный readonly отказ выявил наследование этого атрибута Windows-функцией `fs::copy` в служебную `.bak`. После снятия readonly с основного файла повтор всё ещё падал. Новая создаваемая backup-копия writable; старый идентичный readonly-дубликат исправляется только при writable-оригинале. Отличная по содержимому защищённая предыдущая ревизия не переписывается. Основной readonly-файл не разблокируется. Windows-регрессия проверяет все эти случаи.

## Авторский сценарий

Вместо системного confirm при запуске — отдельный экран: имя, дата, сцены/шаги и фрагмент обеих версий, восстановление, сохранённая версия, резервная копия. Impeccable использован для защищённого выбора и читаемых ошибок в существующей graphite/violet теме. Проверены1440×940/1000×700; screenshot-раунд и подтверждение без открытого цикла полировки.

До выбора нет записей/удалений. Изменения/импорт/создание/открытие других проектов защищены до решения. Можно закрыть окно: обе версии останутся. Восстановление пишет выбранный проект, соответствующую карточку и удаление черновика одним flush. UI открывает редактор только после успеха. Ошибка возвращает staging-кэш и оставляет обе версии/копию в памяти; повтор или последующий отказ не публикует неуспешный draft. Закрытие при операции ждёт очередь (unit-проверка); native закрытие без выбора проверено отдельно.

Восстанавливается допустимое выделение сцены/шага/слоя; импортированные произвольные ключи не становятся состоянием store. Старые wrappers без selection поддержаны. Черновик другого проекта не смешивает сцены и сохраняет существующие карточки. Повреждённый JSON draft сам по себе больше не прячет saved library: можно сохранить исходные байты и явно отказаться. Подтверждение отказа отменяется Escape; простой выход не означает отказ.

Полная копия материализует выбранный проект. При missing media доступна явно помеченная копия со ссылками, без чтения отсутствующего файла. Неresolved transport URL отвергается; буквальный текст истории не преобразуется. Сохранение нативной копии не меняет исходный проект/черновик. Обычный OS dialog сохранён; только validated QA profile пишет в свежую собственную `backups/copy-*` папку без диалога. Payload не может выбирать путь.

Ориентиры: [Blender Recovering Data](https://docs.blender.org/manual/en/latest/troubleshooting/recover.html) различает recovery-копии и сохранённый файл; [VS Code Hot Exit](https://code.visualstudio.com/docs/editing/codebasics#_hot-exit) сохраняет незаписанные изменения для восстановления. Здесь собственный формат и явная операция выбора, не копирование их кода и не обещание бесконечной истории версий.

## Не засчитанные попытки

Первый QA-selector учитывал только span-label «Автосохранение», а enclosing label содержит и options; он остановился до опасного шага. Продолжение выбрало реальный field/select и независимо проверило autosave60/соседний проект/voice/durable draft. Первый crash helper отказался от пути из-за alias/canonical mismatch, затем обычный Node realpathSync упёрся в виртуализованный `C:`. Использован native realpath; защитные проверки профиля не удалялись, ни один процесс до их прохождения не был завершён.

Backup download timeout не засчитан как успех: он привёл к исправлению продукта на native file write. Повтор restore с writable-основным файлом упал из-за readonly `.bak` — тоже продуктовый дефект, не ослабленный QA; исправлен и покрыт Windows-регрессией. QA preview selector ограничен настоящим dialog, чтобы не принять фоновую подпись карточки за проигрывание. Тестовые прямоугольники/тон не выдаются за художественный пример.
