# Предметная игра: проверка и исправления исходников

Исторический исходный этап16 октября2026 выполнялся на0.2.30 без нового установщика. Затем эти исправления и перенос профиля вошли в локальную поставку0.2.31: native UI Save/Build, packaged29/29 и ordinary startup подтверждены; итог — RELEASE_0.2.31.md. Проверки ниже описывают именно исходный этап, не подменяют приёмку новой поставки. Пользовательские проекты, профиль и установленный EXE не изменялись.

## Подтверждённые дефекты

1. Повторный выбор основного требуемого предмета в расширенных свойствах мог очистить ID в `null` и превратить применение в обычное действие. Убрано дублирование; общий patch сохраняет `''` для незавершённого применения. Предпросмотр закрывает доступ, проверка проекта запрещает сборку. Опциональное второе требование для расходуемой вещи по-прежнему можно явно убрать, не меняя основную вещь.
2. Форма аудио принимала старые записи, определённые категорией без MIME, но проверка перед сборкой отвергала их. Тип теперь определяется общей функцией `runtime/audio-model.mjs`. Явный MIME другого типа и отсутствие источника остаются ошибками. Это метаданные, не доказательство доступности/декодирования произвольного старого файла.
3. Потерянные ссылки на предметы теперь видны как «Удалённый предмет · выберите замену», с ошибкой рядом. Исходный ID сохраняется до явного ремонта; первый предмет автоматически не выбирается.

## Проверки

- ESLint: пройден. Полный JS-набор:278/278. Sites:4/4. Production Vite bundle + подготовка Sites: пройдены; предупреждение о JS-чанке больше500 КБ остаётся.
- Изолированный Chromium, текущие исходники: очистка требования, запрет бесплатного применения, отсутствие дублирующего поля, Undo/Redo, исправление выбора, расходование, очистка второго требования, сохранение битого ID.1440×1000 и1000×800: проверены доступность поля/границы и снимки. Исключений renderer в проверке нет. Это не нативный WebView2 и не проверка установленного EXE.
- Настоящий Ren’Py8.5.3, отдельный Windows desktop без переключения ввода/управления мышью владельца:4/4 сценария,62/62 утверждения. Клики, take/use, одноразовость, скрытие, смена изображения, голос/SFX, независимые каналы, ответ только голосом до перехода, Save/Load/Rollback. Повтор с аудио без MIME: также4/4 и62/62, без исключений.
- Runtime работает из скомпилированных исходников, не из нового packaged ZIP. Тестовые записи — тон; актёрская речь/качество звука не проверены. Rust-сборка и новый установщик в этом этапе не выполнялись.

Доказательства: `D:/IstoriyaQA/engine-request-20261016/` — логи команд и снимки; обычный runtime — `IstoriyaQA/prop-runtime-SONzwf/tea-runtime-qa-SvNM71/result.json`, legacy — `prop-runtime-7q4UDo/tea-runtime-qa-NTfvjR/result.json`.

Две неуспешные попытки UI-harness не засчитаны: точное доступное имя включало поясняющий текст, а повтор теста начинался с уже удалённого ID. Исправлены селектор и начальное состояние теста; финальный `--raw run-code` вернул `passed:true` с9 проверками. Первичная визуальная серия просмотрена одним пакетом; дополнительные косметические правки не делались.

## Что можно собирать сейчас

В сценах: «Предмет» → независимый слой → «Добавить реакцию»: осмотр, получение/применение вещи, текст/говорящий, готовая запись голоса, SFX, условие, результат и переход. Шаг «Осмотреть сцену» ждёт игрока. Голос обычной реплики задаётся в её свойствах; звук — в «Добавить звук к действию». Инвентарь и реакции исполняются одними правилами в preview и экспорте, не отдельными декоративными кнопками.

Это предметный движок новелл, не завершённый универсальный RPG-движок. Запись с микрофона/TTS, произвольные мини-игры, бои/физика и вся production-приёмка остаются открыты; остальные этапы PRODUCTION_PLAN.md не отменены.
