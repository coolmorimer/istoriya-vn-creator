# 0.2.34 — игровой мир, камера и ключевые кадры

Сборка и локальная приёмка — 19 октября 2026; подготовка публичной поставки — 21 октября 2026. Проверяемая бета, не декларация завершения всего исходного ТЗ. Автор собирает 2D-новеллу/приключение без кода; Rust/Tauri отвечает за настольное приложение и хранилище, React — за интерфейс, Ren’Py — за готовую игру. Компилятор пока работает через включённый Node worker. Заявления об ускорении без замеров не делаются.

## Что работает

- «Сюжет → Игровой мир»: здоровье, опыт/уровни, навыки, рецепты, точки карты с условиями, NPC и пошаговые противники. Предметы используют существующий инвентарь и реакции сцен. Шаг «Игровое действие» открывает экраны/встречи либо меняет показатель; показатели доступны также условиям/результатам выбора и предмета.
- Крафт проверяет ингредиенты/навык/лимиты до списания. Неудача ничего не расходует. В бою доступен базовый удар и навык; ответ только выжившего противника, XP/добыча один раз. Настраиваются победа/поражение/разговор и переходы к реальным сценам. Это детерминированная ограниченная система, без физики, маны и случайных бросков.
- Предпросмотр и экспорт используют общую модель. Состояние игрока отделено от проекта и сохраняет здоровье, навыки, инвентарь и бой через Save/Load/Rollback. Нет исполнения авторского кода.
- Готовый набор:3 взрослых героя,8 эмоций,2 пустых фона, отдельные стол и сервиз. Импорт героев/четырёх послойных сцен/мини-приключения добавляет отдельную главу одним Undo. Исходные PNG повторно используются без изменения; происхождение в public/assets/packs/tea/ORIGIN.md. Это один набор, не универсальный каталог и не новые сидячие позы/актёрская озвучка.
- Включена работа0.2.33: игровая 2D-камера и ключи фона/героя/предмета,5 интерполяций, редактируемые движения, авторское перетаскивание через обратную камеру, внутренние открепляемые/изменяемые панели. Диалог и меню не перемещаются камерой.
- Формат8 сохраняет чтение старых проектов. Неполные определения можно сохранить черновиком; сборка указывает ошибки. Используемые RPG-предметы/сцены/герои защищены от удаления. Новый проект пустой, игровые системы выключены.

## Фактические проверки

Источники локальной приёмки — verification-manifest.json и qa/ в архиве проверки владельца. Полные QA-профили и логи не публикуются; публичный release-manifest.json содержит хеши и ограниченное резюме. Сборщик итоговых доказательств отказывает при несовпадении EXE/модулей/SHA, провале тестов, отсутствии результатов игр или незавершённом процессе. Неуспешные ранние попытки сохранены отдельно, не засчитаны.

Предпросмотр проверен отдельно: реальный клик PNG после native save/reopen, крафт со списанием и Save/Load, навык/бой/XP/уровень. Переносимый RPG-проект также действительно импортирован через файловый обработчик UI в отдельную пустую native-библиотеку:12 ресурсов,3 героя/8 эмоций,5 сцен, реальные scoped-файлы, запуск и получение припасов кликом. Следующий новый проект пустой, процесс закрыт0. Это не проверка обычного OS-диалога выбора файла. Финальный HUD приключения:85/120 здоровья, уровень2, опыт100. В авторском примере начальный ручной шаг снимает10 здоровья. Два фона и четыре художественные сцены плюс исходная пустая сцена остаются редактируемыми; это краткий механический пример, не обещание пяти минут нового сценария.

Нативный UI тестируется через CDP собственного WebView в отдельном Windows desktop без переключения input desktop и без OS-мыши. QA-режим выбирает только собственную папку вывода; это не проверка обычного системного file picker. Тестовые rpy/слоты добавляются только в распакованные QA-копии, не в поставляемые ZIP.

## Интерфейс и документация

Impeccable использован как проверка расширения существующего графитово-фиолетового интерфейса: формы/list, читаемые русские операции, отдельные определение/партия и явный импорт. Независимый reviewer выдал `fix` для служебных add/subtract/set в свёрнутых результатах. Одна правка/пересборка; actual native показывает «прибавить/вычесть/установить» для всех трёх. Итоговый `ship` относится к этой оценённой правке, не является полной production-сертификацией. Documenter сравнивает расширение с incumbent; отсутствовавшие корневые PRODUCT.md/DESIGN.md не выдумываются и общий дизайн не меняется.
