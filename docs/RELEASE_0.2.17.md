# 0.2.17 — первая игра целиком и исправление UI-сборки

15 октября 2026. Проверяемая бета; весь production-MVP ещё не принят.

## Изменения

- Новый выбор содержит два варианта без автоматического перехода обратно в ту же сцену. Пустые назначения отмечает validator. «Создать сцену для варианта» создаёт настоящую пустую сцену и связь одной Undo-операцией, не уводя автора из текущего выбора; затем доступна кнопка открытия ветки. Нельзя перезаписать уже связанную/устаревшую ветку. Существующие варианты и timed-данные не меняются.
- Поля вариантов расположены вертикально и читаемо; условия/результаты раскрываются отдельно, но не удаляются. Для уточнения авторского процесса изучены официальные материалы [TyranoBuilder о ветках](https://tyranobuilder.com/tutorials/adding-story-branches-and-player-choices) и [управлении персонажами/эмоциями](https://tyranobuilder.com/tutorials/managing-characters). Практический вывод для нашего редактора — явные назначения и доступная правка нужного героя/варианта; исходный код не копировался. Impeccable применён как точечное улучшение Operate-интерфейса, без смены graphite/violet-компоновки.
- Появление героя редактируется прямо в свойствах выбранного на холсте слоя и сохраняется в исходное showCharacter-действие, не перематывая кадр. Кнопка «Открыть игру отдельно» не требует знания названия движка. Неподтверждённая оценка будущего размера ZIP удалена; в сводке остаётся размер записей библиотеки ресурсов.
- **Найден реальный разрыв между CLI и UI**: Tauri передавал `\\?\E:\...\native` в Node как путь главного модуля. Node24.13.1 завершался с EISDIR ещё до запуска worker, хотя --verify-native работал. Теперь эквивалентные Windows-пути runtime/workspace упрощаются с dunce, рабочая папка процесса задаётся явно. Специальные namespaces не переинтерпретируются. Native-строки ошибок превращаются в Error с сохранённым сообщением, вместо общего «Не удалось собрать игру».

## Сквозной сценарий раздела95

В финальном EXE на отдельном non-input desktop, через реальные элементы WebView, выполнено **одной цепочкой, без импорта готового .vnproject**:

пустой1920×1080 → фон → новый герой → три PNG и названия эмоций → сцена → drag на холсте → реплика → музыка35%/loop → появление справа → выбор → две новые сцены/связи/Undo/Redo → собственное окно диалога и импорт TTF → preview обеих веток/Save/Load → **Windows Build кнопкой редактора** → save/home/reopen.

Проект «Две тропы — первая история»:3 сцены,1 герой/3 эмоции,3 фона, музыка и шрифт. Всего8 медиа:6 записей библиотеки и2 legacy-compatible inline-спрайта из карточки героя. Они остаются самостоятельными PNG, не склеиваются с фоном. Это короткий функциональный пример, не новый пятиминутный художественный сюжет; прежний «Чай вместо подвига» сохранён.

При QA-сборке выход автоматически ограничен собственным QA-профилем; обычный запуск по-прежнему показывает native folder-picker. Это проверка настоящей UI-кнопки/IPC/worker/сборки, **не** автоматизация выбора папки мышью. Сам OS-диалог остаётся непроверенным.

Отдельно после полного нового процесса импортирован полученный portable-файл через настоящий HTML file-input handler редактора. Сохранённый тестовый слот выбора остался совместимым, ветка снова пройдена. Нативный OS file-picker не управлялся. До первого Windows Build никакого готового проекта в этом профиле не импортировалось.
