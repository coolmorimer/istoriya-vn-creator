# 0.2.22 — библиотека без тысяч лишних карточек

16 октября 2026. Локальная проверяемая бета. Полная матрица production-MVP остаётся открытой.

## Что изменилось

Поиск по названию ресурса и исходному имени файла работает вместе с категориями, учитывает регистр и NFC. Список показывает только видимую область и небольшой запас, но все результаты доступны прокруткой, стрелками, Home/End. Фокус остаётся на списке при замене DOM-карточек. «Добавить файлы» доступно даже при пустом результате поиска.

Места использования индексируются одним обходом проекта. Один и тот же список определяет счётчик и навигацию. Учитываются инвентарь, галерея, шрифты реплик, записи/изображения реакций, портреты/спрайты, старые inline-источники, оформление и метаданные. Явная ссылка одной записи не присваивается другой записи с тем же файлом. Один элемент UI не считается дважды через legacy-поле и layout; два разных состояния кнопки остаются двумя местами. Старые реакции без ID не схлопываются. «Где используется» ведёт к конкретному слою/реплике, герою, вещи, оформлению или настройкам.

Impeccable применён к измерению и устранению блокирующего UI-пути, а не смене визуальной темы. Библиотека сохраняет graphite/violet, поиск/кнопки сверху, свойства справа. Высота списка берётся из фактического flex/grid рабочего пространства, не из вычета предполагаемой высоты шапок. На1000×700 список заканчивается на671px и остаётся прокручиваемым; свойства имеют собственную прокрутку. Визуальная проверка ограничена одним раундом1440×940/1000×700, одной группой исправлений и подтверждением, без бесконечной полировки.

Функциональный ориентир — [Unity Project window](https://docs.unity.com/en-us/engine/6000.7/manual/unity-editor/editor-windows-views-reference/project-view): найти файл и работать с выбранным ресурсом, не листать вручную всю библиотеку. Технический подход соответствует [React: virtualize long lists](https://legacy.reactjs.org/docs/optimizing-performance.html#virtualize-long-lists) и [useMemo](https://react.dev/reference/react/useMemo). Это собственная реализация; чужой код и язык поисковых выражений автора не добавлены.

## Измерение до и после

Один собственный native-профиль:10 глав,500 сцен,5000 шагов,5000 разных валидных32×32 PNG. Суммарно5640733 байта медиа, workspace JSON около8,7 MB. PNG дополнены синтетическим payload для уникальности; это технические цвета, не художественный пример. Старый0.2.21 и окончательный0.2.22 открывают один проект, production UI, viewport1440×940, по3 входа в раздел ресурсов.

Замер охватывает программное нажатие и два requestAnimationFrame, содержит CDP/Playwright overhead. Это конкретная тёплая операция, не холодный запуск, FPS, физическая клавиатура или научно устойчивый perf-тест. Неочищенный WebView heap записан как наблюдение, но не используется для утверждения о снижении пиковой RAM: моменты GC не контролировались.

## Исправленная промежуточная ошибка

В первом кандидате виртуальный список был ограничен формулой100dvh-320px. При переносе toolbar/фильтров на1000×700 его низ оказался на746px. Кандидат не принят по геометрии, исходный receipt сохранён; заменено на flex/grid по реальному остатку высоты. Финальный повтор подтвердил bottom671/height271, выбранный5000-й ресурс не потерян. Проверка не ослаблялась.
