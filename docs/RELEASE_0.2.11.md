# 0.2.11 — игровые ветви прямо на карте

Проверяемая бета от15 октября2026. Карта стала местом настройки игровой логики, а не только просмотра линий. Полный production-MVP ещё не принят.

## Работа автора

- Выберите линию выбора на карте сцен **или глав**: вопрос игроку, текст варианта, назначение, составные условия доступности и несколько результатов редактируются здесь же. Используются те же no-code поля и реальные записи проекта, что в сценарии.
- Условная связь показывает правило и объясняет «Если да / Если нет». Обе линии редактируют одно правило, а не две независимые проверки.
- Переходы реакций предметов отображаются на обеих картах, включая назначения на вход главы. Можно изменить подпись, назначение, условия/результаты и открыть сам предмет. Удаление такой связи удаляет только назначение: ответ, одноразовость, эффекты и реакция остаются. Undo возвращает переход.
- «Показать сцену назначения» снимает фильтр главы, выбирает и прокручивает карту к назначению. При смене фильтра свойства относятся к видимой сцене; первая сцена другой главы больше не обозначается началом всей игры.
- Карта занимает больше высоты: повторяющий заголовок убран из визуального потока, разделы и навигация сохранены. В1000×700 нижняя часть панели больше не выходит за окно. Поля прокручиваются внутри панели, а не обрезаются.
- Полноэкранные карты удерживают клавиатурный фокус, Escape закрывает их. Масштаб под курсором проверен в браузере; сохранены кнопки, ползунок, панорамирование и отдельные карты глав/сцен.

Impeccable использован для контекстных полей, сохранения существующей графитово-фиолетовой компоновки и одной ограниченной партии исправлений после проверки1440×940/1000×700. Новая визуальная система не вводилась. Снимки: `output/playwright/maps-0211-final-{1440,1000}.png`. При «Показать всё» карточки большой схемы закономерно мелкие: нужен zoom/fullscreen; это не автоматическая читаемая раскладка всех плотных графов.

## Выбранные ориентиры

Официальная [документация Twine](https://www.twinery.org/reference/en/editing-stories/linking-passages.html) связывает реальные переходы истории с направленными линиями карты. [articy:draft](https://articy.com/help/adx/Flow_PinsConnections.html) позволяет настраивать условия и последствия в flow-контексте. Наш вывод: автор должен видеть игровые переходы, включая предметные, и настраивать их без поиска отдельного шага в другом разделе. Это собственная no-code реализация поверх формата проекта, не копирование их интерфейса/исходников и не внедрение скриптового языка.

## Исправления данных

- `storyGraph.sceneExits` включает предметные реакции; `exitObject/updateExit` изменяют конкретный вариант/реакцию/условие. Устаревшая ссылка после замены управляющего действия не может перезаписать новое действие.
- Удаление последнего перехода сохраняет timeline-параметры. Новое управляющее действие timed-сцены добавляется после конца существующих включённых клипов; отключённый поздний клип не отодвигает его. Монтаж не конвертируется автоматически и старые клипы не перемещаются.
- Несколько импортированных результатов без ID сохраняются при правке одной строки. Технические поля chapter/scene разрешаются существующим общим маршрутизатором: смена входа главы влияет на переход без ручной правки всех ссылок.
- Формат остаётся **schema4**; schema1–3 читаются. Условия/результаты исполняются общим модулем0.2.10, а не отдельными «картографическими» правилами.
