# 0.2.31 — папка данных, безопасное закрытие и требования предметов

16 октября 2026. Проверяемая локальная бета; полная production-приёмка остаётся открытой.

## Для автора

На главной и в настройках появился пункт «Хранилище редактора». Можно выбрать другой диск: редактор создаёт новую отдельную папку, копирует библиотеку и необходимые медиа, проверяет SHA-256 и только после этого предлагает перезапуск. Во время копирования и ожидания перезапуска авторские изменения/сборка заблокированы. Доступны отмена и явный возврат к предыдущему профилю. Перенос не создаёт демонстрационных проектов: пустая библиотека остаётся пустой.

По умолчанию переносятся компоновка панелей, сворачивание глав, отдельные тестовые сохранения редактора и настройки проигрывателя. Их можно явно не переносить. Это не сохранения готовой Ren’Py-игры. Кэш окна создаётся заново на выбранном диске; его физическое содержимое не копируется. Временные файлы дочернего компилятора теперь создаются внутри выбранного профиля, без изменения пользовательских переменных Windows.

Исходная папка и созданные копии **не удаляются**: перенос не освобождает место автоматически. Внешние файлы `.vnproject` остаются в своих папках; их регистрации не переписываются. Возврат переключает между копиями, не объединяет изменения. Если выбранный диск/папка недоступны, редактор показывает восстановление до загрузки библиотеки, а не подменяет её пустой историей. Ссылка на выбранный профиль остаётся в исходной системной папке: она должна быть доступна для записи.

Закрытие больше не зависит от успешного сохранения внутри App: при отказе записи доступно отдельное подтверждение «Вернуться в редактор» / «Закрыть без сохранения». Отмена сохраняет изменения в памяти; повтор записи после восстановления доступа действительно сохраняет их. Во время переноса закрытие запрашивает отмену, не записывая проект в неподходящую копию.

Исправлено применение предмета: дублирующий селектор мог очистить требование и сделать действие бесплатным. Теперь основной селектор один, пустой выбор остаётся незавершённым применением, preview закрывает доступ, проверка запрещает сборку. Удалённая вещь видна с ошибкой и исходным ID до явной замены. Старые аудиозаписи без MIME обрабатываются одинаково в форме и проверке проекта; явный неверный MIME/отсутствующий источник не принимаются. Проверка метаданных не доказывает доступность или декодирование любого файла.

Во время native-проверки найден и исправлен сброс свёрнутой главы при первом открытии проекта. Автораскрытие выполняется при настоящем переходе к сцене или команде «К текущей», не при первоначальном восстановлении компоновки.

## Хранение и защита

Каждый выбор создаёт свежий `Istoriya-profile-*`, без слияния с занятой папкой. Копируются только известные файлы редактора; ресурсы из объявленных доверенных источников материализуются в content-addressed assets. Литеральный текст истории не переписывается. Сохраняются исходные workspace JSON отдельно от перенесённого документа и манифест проверенных файлов. Отмена/ошибка не удаляет ни исходник, ни уже созданную часть копии. Изменение исходного файла во время копирования останавливает перенос.

Выбор профиля проверяется по маркеру/ID/формату/каноническим каталогам; символические ссылки вместо служебных файлов отвергаются. Повреждённый выбор сохраняется перед явным возвратом. Импорт UI выполняется транзакцией IndexedDB с отдельным receipt; повтор не переписывает уже импортированные слоты. Native ack выдаётся только после успешного восстановления. Ошибки UI-импорта показываются до App и допускают повтор.

Ориентиры разделения data/cache/temp и выбора папки ресурсов — [официальный portable-режим VS Code](https://code.visualstudio.com/docs/setup/portable) и [управление ресурсами Krita](https://docs.krita.org/en/reference_manual/resource_management.html). Код этих приложений не копировался.
