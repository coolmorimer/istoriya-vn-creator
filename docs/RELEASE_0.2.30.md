# 0.2.30 — диагностика и восстановление после ошибки

16 октября 2026. Проверяемая локальная бета. Полная production-приёмка и весь исходный запрос остаются открытыми.

## Изменения

Пункт90 исходного ТЗ получил технический журнал и отдельное окно «Диагностика редактора». Оно доступно с главной, из настроек, при ошибке сохранения, восстановлении черновика, ошибке React и сбое загрузки самого App. Окно размещено вне проектного ErrorBoundary и не зависит от библиотеки проектов. По умолчанию показаны версия, состояние журнала и свободное место в профиле, без traceback. Подробности раскрываются явно.

Rust фиксирует исходы операций хранилища, импорта/экспорта, сборки и запуска; интерфейс — window-error, unhandled rejection, render и bootstrap. Записи содержат время, операцию, длительность, исход, категорию/отпечаток ошибки и числовые координаты JS-кадров. RPC payload, исходные сообщения исключений, пути, названия проектов, тексты истории, медиа и environment не сериализуются. Копируемый JSON также не содержит пути профиля. Сам путь виден только в раскрытых локальных подробностях.

Журнал: `logs/editor.jsonl`, `editor.1.jsonl`, `editor.2.jsonl` внутри профиля; максимум3×256 КиБ. В отчёте — последние64 события, в очереди renderer — максимум16 незавершённых записей. Переполненная очередь может пропускать события; это не полный crash dump. Чужие поля повреждённой записи отбрасываются. Ссылки/необычные типы файлов/слишком большой существующий журнал не перезаписываются. Ошибка записи оставляет текущие события в памяти и не отменяет успешное сохранение проекта. Вспомогательные журналы используют обычные OS-buffered writes, не аппаратный fsync на каждое автосохранение; гарантия сохранности журнала при отключении питания не заявляется.

«Скопировать техническую информацию» формирует отчёт в native-части и копирует Unicode через Win32 clipboard. «Открыть папку журналов» открывает только canonical-каталог собственного профиля через ShellExecuteW; RPC не принимает произвольный путь/команду/тело буфера. При отказе копирования показываются ошибка и ручное выделение отчёта. В QA эти два действия заменяются явными ограниченными файловыми receipts: системный буфер владельца и Проводник не затрагиваются. Обычные Win32 clipboard/Explorer действия пока не приняты вручную. В браузере явно указан журнал только в памяти, кнопка папки недоступна.

При свободном месте профиля менее1 ГБ показывается предупреждение. Оно не переносит каталог, не резервирует место и не гарантирует достаточный объём для конкретной игры. Установка редактора на D: по-прежнему не переносит обычный профиль с C:. Пользовательские переменные и профиль не изменялись.

Референс организации поддержки — [официальная документация Krita](https://docs.krita.org/en/reference_manual/sharing_krita_logs.html): доступные из приложения технические сведения и локальные журналы. Код/фреймворк не копировался. Использованы официальные контракты [Tauri commands](https://v2.tauri.app/develop/calling-rust/), [Win32 clipboard](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard), [ShellExecuteW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew), [GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw).

## Найденные дефекты

- Повторная быстрая загрузка поймала реальную регрессию имени: «Печать» превратилась в «печатьПечать». Прежнего focus-ref guard вокруг позднего setName оказалось недостаточно. Подстановка имени перенесена в discrete file/resource-selection до async decode; единственный локальный flushSync фиксирует DOM поля до браузерного focus/selection. Во время печати/в render/effect/после decode он не вызывается и не является авторской транзакцией. Повторная загрузка не меняет уже редактированное имя, включая намеренно пустое. Контракт — [React flushSync](https://react.dev/reference/react-dom/flushSync); использование ограничено подтверждённой гонкой, не всем редактором. Отрицательное native-состояние и проверки задержанной загрузки/быстрых переименований сохранены отдельно.

- getClientRects возвращал прямоугольники скрытых полей внутри закрытого details. Tab выходил из диалога. Общий visibleDialogControl проверяет фактическую видимость и закрытые details; применён в диалогах диагностики, предметов, реакций, героя, фона, поиска и карты.
- Rust отвергает command строкой; первоначальный diagnostic caller терял её message. Добавлена общая nativeError-нормализация, не заглушка успеха.
- Отключение активной кнопки на время async-copy снимало focus на BODY. Диалог временно удерживает focus и восстанавливает только своё управление, не перехватывая уже выбранное пользователем поле. Escape/Tab остаются внутри.
- fsync каждой вспомогательной записи на D: сделал ранний4500-записный stress-test длительностью146,91с. Убрана именно синхронизация журнала, не durable-checkpoints проектов. Ротация проверяется заполненными собственными файлами без тысяч бессмысленных физических flush. Это не замер общего ускорения редактора.
- Installer из Node/PowerShell7 встретил конфликт types/format data при автозагрузке Windows PowerShell Security. Используются cmdlets собственной версии shell; проверка подписи Microsoft WebView2 не отключена.

Отдельно сохранены отрицательные кандидаты и QA-ошибки: разовый rustc STATUS_ACCESS_VIOLATION (повтор того же завершившегося процесса прошёл); преждевременный disk-read после асинхронного save; сравнение изменённого явным Save modifiedAt; пересекавшиеся QA-команды и minified alias store. Они не считаются успешными тестами и не исправлялись подавлением исключений. Предварительные установщики сохранены отдельно, не подменяют финальный.

## Границы

Нет автоматической отправки/телеметрии, синтеза/записи речи, полного Rust-порта компилятора или универсального RPG-движка. Генератор остаётся встроенным JS/Node worker, игра — Ren’Py. Обычные OS-диалоги, clean Windows/upgrade/rollback, коммерческая подпись, все физические DPI/устройства и качество слышимой озвучки остаются открытыми.
