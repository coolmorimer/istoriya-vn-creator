# Rust план переходов истории

В локальной 0.2.38 нативные build/preview используют `StoryPlan` из `crates/istoriya-core/src/story.rs`. Это навигационная часть будущего промежуточного представления игры: вход, последовательность сцен и типизированные назначения. Исполнение условий, временных событий, анимаций и игровых правил ещё не перенесено целиком в Rust.

## Источник данных и порядок

Авторский `.vnproject` остаётся источником истины. План заимствует ID и не меняет документ, не добавляет поля и не копирует медиа.

1. Начало игры — входная сцена первой непустой главы. Без явно выбранного входа используется первая сцена этой главы. Явный запуск сцены/шага в предпросмотре имеет приоритет.
2. Последовательность берётся из списков глав с удалением повторного членства. Сцены вне глав добавляются после них в стабильном UTF-16 порядке ID, одинаковом для Rust и JS.
3. Для каждого ID сохраняется следующая сцена или отсутствие продолжения. Явные переходы, выборы, условия и конец истории сохраняют свою семантику; план не заменяет их последовательным переходом.
4. Назначение на главу разрешается через её текущий вход, даже если рядом осталась старая кэшированная ссылка на сцену. Ссылка на сцену с буквальным ID `chapter:third` остаётся ссылкой на сцену — Rust не интерпретирует строковые префиксы интерфейса.

Эти правила также используются совместимым JS-экспортом, картой, проверкой достижимости и предпросмотром. Исправлены игнорирование входа первой главы и расхождение в продолжении через сцены вне глав. Исходный порядок списков и координаты карты не переписываются. Для свободных сцен порядок теперь стабилен после сохранения и повторного открытия, а не зависит от порядка ключей JSON.

Импорт больше не присоединяет свободные сцены к первой главе. Дерево показывает их в служебной группе «Вне глав», которая не записывается как новая авторская глава. Поиск, сворачивание и навигация к текущей сцене работают и в этой группе. Поле «Глава» на карте позволяет явно назначить или снять принадлежность с Undo/Redo. При переносе входной сцены очищается прежний вход главы; назначение на саму главу продолжает вести через её действующий вход. Уже сохранённые старой версией назначения не угадываются и автоматически не отменяются.

Явная автораскладка карты включает служебную группу и сохраняет только позиции её реальных сцен. Самой новой главы в документе не появляется; Undo восстанавливает прежние позиции всех сцен.

## Состав плана

- `startSceneId`, `startActionId` — подтверждённый запуск.
- `sceneOrder`, `nextScene` — канонический порядок и продолжение.
- `chapterEntries` — разрешённые входы глав.
- `transitions` — адрес исходного поля и назначение типа Scene или Chapter с разрешённым SceneId.

Обработаны jump, оба плеча condition, варианты choice, реакции предметов, локации и сцены NPC/победы/поражения включённого игрового мира. Отключённые timed-действия не исполняются и не требуют действующего перехода; в последовательной сцене прежнее поле отключения timed-клипа не выключает шаг.

Проверка блокирует сборку при удалённом назначении, незаполненном обязательном переходе, пустом выборе, повторном ID главы, повреждённом списке сцен, неверном входе главы или устаревшем шаге запуска. Диагностика возвращает точный адрес и контекст сцены/шага. Проверка выполняется до подготовки SDK и не запрещает сохранение незавершённого авторского проекта.

## Передача генератору

Rust записывает исходный документ в фиксированный `document.json`, план — в `story-plan.json`. Для обоих файлов передаются длина и SHA-256. JS-worker проверяет целостность и использует подготовленный план вместо `resolveStoryProject`.

`runtime/native-story-plan.mjs` создаёт изменённые представления только для родителей разрешённых ссылок. Неизменённые сцены, действия и ресурсы сохраняют общие ссылки; отсутствующий старый ID сцены добавляется только в представление генератора. Экспорт исходного авторского проекта остаётся неизменённым.

Это внутренний контракт доверенных процессов, не аутентификация против пользователя, способного изменить оба файла и их хеши. Генератор по-прежнему читает JSON целиком, поэтому отказ от глубокого клонирования не является измеренным ускорением или доказательством снижения общей памяти.

## Проверки

`npm run verify:story` собирает настоящий Rust-инструмент `story-contract` и сравнивает его результат с общими JS-правилами на 424 проектах: 411 корректных и 13 с заданными ошибками. Сравниваются вход, порядок, продолжение и 7039 назначений; для повреждённых ссылок проверяются код и точный адрес ошибки. `native:test` включает этот корпус и 12 тестов Rust-навигации.

`npm run verify:rust-engine` в собственной QA-копии отключает старые JS-builder, GUI-launcher, структурный валидатор и `resolveStoryProject`. Так успешная сборка не может быть подтверждением старого пути под новым названием.

`npm run verify:story:runtime` проверяет настоящий EXE и готовую Windows-игру: непервый вход главы, переход предмета в главу, оба условия, буквальный ID сцены, продолжение вне глав, Save/Load и обычный старт. Опция `--ui-receipt <ui-build-result.json>` проверяет пакет реальной UI-сборки на ограниченном QA-профиле вместо новой CLI-сборки. Фактические результаты конкретной версии фиксируются отдельно в её отчёте.

Ни тестовый инструмент, ни этот план не являются собственным Rust-проигрывателем. Остальные части [плана R1–R8](RUST_ENGINE_PLAN.md) сохраняют полный объём работ.
