# 0.2.20 — взаимодействия как единая авторская операция

16 октября 2026. Локальная проверяемая бета. Полная production-приёмка и универсальный RPG-движок не объявляются завершёнными.

## Что добавлено

В свойствах предмета → «Добавить реакцию» открывается единая форма. Автор выбирает осмотр/ответ, получение вещи, применение вещи или скрытие предмета. Имя, описание и иконка инвентаря создаются здесь же; не нужно сначала выходить в «Сюжет». При применении расходование включается отдельно. Первую вещь из списка редактор автоматически не подставляет.

В той же операции можно настроить ответ, говорящего, готовую голосовую запись и SFX, громкости, смену изображения, переход к сцене/главе, условия, несколько результатов, однократность, скрытие и создание шага осмотра. Дополнительные настройки раскрываются по необходимости. Окно вынесено поверх панелей; основная кнопка остаётся доступной при высоте700px, Tab не выходит наружу, Escape отменяет форму.

Новая вещь, записи, реакция и осмотр фиксируются одной операцией Undo. Отмена и ошибки чтения не создают объектов. Все ссылки и захваченные project/scene/layer проверяются до первой мутации. Повторно загруженная одинаковая запись переиспользуется. Явный ноль громкости сохраняется.

Это не отдельная «логика формы»: записываются существующие поля schema6. Preview, карты, инвентарь и Ren’Py исполняют прежние общие правила. Дополнены редактор существующей реакции и защита незавершённого применения: отсутствие выбранной вещи блокирует действие и сборку. Отключение расходования не удаляет второй обязательный предмет и количество из импортированных реакций — требования остаются обычными визуальными условиями. Исправлен общий выбор аудио: неправильный image MIME не считается голосом лишь из-за категории; старый ambience без MIME совместим.

Направление и доступный авторский путь: [ENGINE_SCOPE.md](ENGINE_SCOPE.md). Impeccable применён к единой форме и отказам/отмене, сохраняя существующую graphite/violet оболочку. Аудиосемантика сверена с [официальным Ren’Py audio](https://www.renpy.org/doc/html/audio.html); чужой редактор или его код не копировались.

## Ограничения

QA использует CDP собственного WebView и SDL testcases на non-input desktop. OS input и переключения input-desktop нет; обычные системные file/folder pickers не проверялись. Тестовый тон проверяет декодирование/каналы, не слышимое качество актёрской речи. PNG-прямоугольники — функциональные QA-фикстуры, не новый художественный пример.

Восстановление отсутствующих медиа остаётся незавершённой отдельной работой; незадействованные начатые mediaRepair-модули не выдаются за готовый relink UI. Не завершены произвольные анимации предметов/камера/keyframes, вся точность старого timed-монтажа, нагрузка500 сцен/5000 ресурсов, DPI/UNC/long paths, clean Windows/upgrade/rollback и коммерческая подпись. Новых иллюстраций, TTS, микрофонной записи, полного Rust-порта генератора или универсальных мини-игр здесь нет. Старые проекты, художественный пример и установщики сохранены; публикации и автоматической установки нет.

## Не засчитанные попытки QA

Первый скрипт пытался нажать Save за защищённой формой — backdrop корректно не пропустил нажатие; скрипт исправлен. Другой повторно переключал уже раскрытое «Применить» в инвентаре, скрывая цели: теперь тест учитывает aria-expanded. Сравнение отмены по всему JSON ошибочно учитывало обычный `modifiedAt` явного сохранения; сравнение исправлено только для этого timestamp, все остальные данные сравниваются полностью. Ещё один selector не учитывал включённую в label подсказку; исправлен только QA-selector, исходный toggle отменён штатным Undo. Первый packaged-case `tea-runtime-qa-Bf1g2v` ошибочно сравнивал Ren’Py `_last_say_who` с видимым именем. SDK8.5.3 `ast.py` хранит там имя выражения; финальная проверка сравнивает его с ID Character и отдельно проверяет текст реального виджета имени. Неудачный прогон сохранён и не засчитан. Продуктовые проверки и подтверждения ради прохождения не отключались.

Первый SHA-прогон `tea-runtime-qa-uem89Y` сопоставлял записи по порядку завершения параллельного чтения, а не по ID ресурса. Исправлен QA-генератор: ожидаемые digest привязаны к конкретным resource IDs. Повтор29/29 прошёл на том же ZIP; байты продукта ради проверки не менялись. Оба failed-result/log сохранены.
