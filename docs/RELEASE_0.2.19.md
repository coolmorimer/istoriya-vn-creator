# 0.2.19 — загрузка медиа по запросу и безопасная аварийная копия

16 октября2026. Локальная проверяемая бета, не завершённая production-приёмка.

## Что изменилось

Rust `load` больше не превращает всю сохранённую библиотеку ресурсов в base64. Интерфейс получает файловые ссылки; изображения, звук и шрифты читает встроенный asset protocol Tauri по запросу. Scope изначально пустой: выдаются только конкретные канонические файлы поддерживаемых медиа, без wildcard-папок. Учтены Кириллица, пробелы, `#` и `%`. Объявления старых inline-спрайтов тоже преобразуются; текст реплик остаётся неизменным.

Renderer URL существует только в памяти окна. Перед записью, сборкой, отдельным запуском и экспортом он возвращается в durable file URI. Исходный snapshot pending-записи сравнивается отдельно от преобразованного batch: параллельная правка не теряется. Компилятор повторно проверяет доступ к файлам и получает file URI вместо загрузки всей библиотеки. Посторонние/временные ссылки не копируются в игру.

Переносимый экспорт материализует только выбранный проект и сообщает о недоступных ресурсах, а не молча выдаёт неполную копию. Аварийная копия работает и при отказе записи: сначала запрашивает медиа у native read-only операции. При пропавшем файле явно доступна «Копия со ссылками» с предупреждением о папке ресурсов. В ней нет временных адресов окна и сохраняются ещё не записанные правки. Сообщение записи содержит понятную причину/действие на русском и технические подробности.

Старые native-выпуски иногда сохраняли медиа как `.bin`. Их совместимость сохранена через сигнатуру: при `load` читается не больше1024 байт такого файла, не всё содержимое. Произвольный `.bin`-документ не становится медиа. Новые GIF/BMP/ICO/AVIF/WOFF получают подходящее расширение; это не обещание проверки всех форматов во всех режимах Ren'Py. Схема проекта остаётся6.

Миниатюры библиотеки, списка сцен и каталога грузятся лениво; активный холст не переведён на отложенную загрузку. Impeccable применён точечно к производительности и восстановлению, с сохранением graphite/violet оболочки. Подход изучен по первичным материалам [Tauri asset scope](https://v2.tauri.app/security/asset-protocol/), [convertFileSrc](https://v2.tauri.app/reference/javascript/api/namespacecore/#convertfilesrc) и [провайдеров ресурсов Naninovel](https://naninovel.com/guide/resource-providers); их код не копировался.

## Найденные неудачные прогоны

Все сохранены, не засчитаны как успешные:

- Первый WebView `run-saBjhB` выявил реальную CSP-блокировку asset URL. Добавлены только локальные endpoints в img/font/media/connect directives и регрессия; политика не заменена разрешением любых адресов.
- Первая game fixture `tea-runtime-qa-8rPUUn` вызывала Start внутри уже идущей игры и получила JumpOutException. Переход к последней сцене вынесен в отдельный testcase; продуктовый код для подавления исключения не менялся. Промежуточный39-assertion прогон также не заменяет финальный41 с `.bin`.
- При параллельных `desktop` и `native:test` возник EBUSY на копируемом SDK CSS. Теперь общий mutex держится до конца синхронизации и hash guard, а не только до завершения Cargo. Повторный параллельный запуск показал реальное ожидание второй команды и успешное завершение обеих. Первые сообщения mutex пришлось сделать ASCII для Windows PowerShell5 без BOM; добавлена проверка кодировки.
- Первый повторный UI-сценарий не подтвердил перезапись уже занятого test-slot. QA исправлен: нажимает настоящее «Перезаписать». Это не отключение подтверждения в продукте.
