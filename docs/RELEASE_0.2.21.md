# 0.2.21 — медиа, которые можно восстановить

16 октября 2026. Локальная проверяемая бета интерактивного конструктора. Предметы, инвентарь, озвучка и SFX остаются настоящими игровыми действиями; этот выпуск укрепляет работу с их файлами. Полная production-приёмка и универсальный RPG-движок не объявляются завершёнными.

## Авторский путь

«Сцены → Предмет» либо ПКМ добавляет самостоятельный слой. «Добавить реакцию» связывает осмотр, получение или применение вещи, ответ героя, голос, SFX, условия/результаты и переход. «Осмотреть сцену» ждёт игрока. Для обычной реплики используется «Озвучка реплики», для другого шага — «Добавить звук к действию». Это существующие функции0.2.20, повторно проверенные в игре после восстановления медиа.

Новый путь: «Ресурсы → Проверить и восстановить файлы». Можно выбрать отдельный файл или папку, подготовить совпадения, просмотреть неоднозначные имена и явно выбрать правильный путь. Только отмеченные подготовленные строки применяются, одним Undo. Неправильное изображение/аудио/шрифт отвергается до изменения проекта. Новые импорты тоже валидируются целым пакетом; позднее чтение после смены проекта не добавляет файлы в другую историю.

Сохраняются имена, ID, основной и именованные спрайты, inline-алиасы старых фонов/UI/портретов, размеры и положение, реакции и результаты. Замена выбранной записи не присваивает ссылки другой записи с тем же исходником. Явное изменение медиа делает прежний тестовый save несовместимым; Undo возвращает совместимость. Физически исправленный файл при Undo снова не повреждается.

Rust проверяет доступность объявленных источников вне save mutex и выдаёт только точные канонические файлы. Доступность не означает исправный кодек. При восстановлении повреждённого managed-cache старые байты сохраняются в `assets/corrupt-*.bak`; внешние исходники не переписываются. Компиляция и portable-export проверяют SHA hash-named файлов выбранного проекта и останавливаются при несовпадении. Обычная загрузка не хеширует всю библиотеку.

Impeccable использован для читаемого отдельного рабочего пространства, видимых подготовленных путей, ошибок и фиксированной кнопки подтверждения в малом окне. Сохранена graphite/violet оболочка. Явный выбор неоднозначного файла согласуется с [официальным workflow Locate and Link Offline Files](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/locate-and-link-offline-files.html); чужой редактор или код не копировались.

## Исправленные сбои и не засчитанные попытки

Первая настоящая UI-сборка обнаружила продуктовый `ReferenceError: projectResourceSize is not defined` после удаления старых импортных helpers. Vite успешно собирал этот код. Восстановлены `projectResourceSize` и `formatBytes`, добавлены ESLint no-undef в обязательный build и регрессия статической защиты. Финальная UI-сборка повторно прошла на исправленном EXE; исходный console-log сохранён. Проверки не отключались.

В промежуточном кандидате native audit возвращал file URI вместо исходного renderer URL и терял соответствие строки; adapter теперь проверяет порядок/идентичность и возвращает исходную ссылку. При выборе неоднозначного пути dropdown ранее сбрасывал отображение: выбранный путь сохраняется. Эти случаи исправлены до финального прогона.

Один QA-скрипт совмещал открытие file-picker и setInputFiles, оставив очереди file-chooser и не выдав Result. Этот вызов не засчитан; глобальная замена повторена отдельными CLI click/upload/verify с сохранённым положительным receipt. Исходное поведение продукта ради QA не менялось.
